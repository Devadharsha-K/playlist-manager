Under the hood

Each song is a node holding a pointer to the previous and next song.

Why this project uses a doubly linked list

A doubly linked list is a chain of nodes. Each song is one node holding its data plus two pointers: prev (the song before it) and next (the song after it). The list also remembers its head (first song) and tail (last song). A playlist keeps changing: songs are added, removed, skipped forward and skipped back. That is exactly what this structure handles well.

Next song · O(1)current = current.next
One pointer hop, no matter how long the playlist is.
Previous song · O(1)current = current.prev
This is why the list is doubly linked. A singly linked list has no back pointer, so going back would mean walking from the head: O(n).
Add or remove · O(1) at the endsOnly a few pointers are re-linked. An array would shift every element to insert at the front: O(n).
Repeat allAt the tail, next is null, so the player jumps to head. At the head, previous jumps to tail. The tail pointer makes both instant.
Reverse · O(n)Swap prev and next in every node, then swap head and tail. No new memory is used.
The trade-offJumping to song number 7 is O(n) because you must walk the chain, and each node stores one extra pointer. An array is faster for that, slower for the rest.
// add a song at the start (addFirst)
node.next = head;      // new node points forward to the old first song
head.prev = node;      // old first song points back to the new node
head = node;           // the list now starts at the new node
